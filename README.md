# 计算机学院晚点名报备

面向中国石油大学（华东）计算机学院的晚点名工具。学生完成定位打卡或离校报备，班级负责人汇总本班回执，管理员发布任务并查看年级进度。项目使用原生 HTML、CSS、JavaScript 和 IndexedDB，无需安装前端依赖或运行后端。

| 入口 | 主要功能 |
| --- | --- |
| 学生端 | 查看任务、定位打卡、离校报备、下载个人回执 |
| 班级负责人端 | 查看本班进度、批量导入回执、生成提醒、导出与报送 |
| 管理端 | 发布、延期和撤销任务，查看报送覆盖与完成率，导出年级数据 |

## 本地预览和部署

在仓库根目录运行下列命令，然后访问 `http://localhost:8765/`。

```powershell
python -m http.server 8765 --directory dist
```

点击首页的「体验演示」可以立即查看三个端。学生端提供「模拟校内」和「模拟校外」，演示记录与正式记录分别保存。

正式部署时，把 `dist/` 作为 HTTPS 站点的发布目录。不同域名、协议、端口和浏览器使用各自的本机数据。启用正式定位前，需在实际使用的手机浏览器内测试许可、精度和围栏边界。

## 登录与账户文件

首次在一个浏览器登录时，填写用户名、密码，并选择本人的账户 JSON。浏览器保存账户后，后续输入用户名和密码即可进入对应工作台。退出登录位于各端顶部，退出后仍保留此浏览器里的本机工作记录。登录会话最长 8 小时。

| 角色 | 用户名 | 密码 | 首次登录结果 |
| --- | --- | --- | --- |
| 学生 | 学籍姓名 | 学号 | 进入学生端，打卡及报备回执自动填入姓名、班级和学号 |
| 班级负责人 | 大写 `A` + 学籍姓名 | 学号 | 进入本人所属班级，可导入并查看该班名单和回执 |
| 管理员 | `admin` | 签发账户时设定的密码 | 进入管理端，初始化全部学籍和负责人名单 |

真实账户文件单独保存在项目外，由管理者将个人文件分别发给对应学生或负责人。管理员账户文件只保存在管理员设备。学生和负责人各使用一个文件，即使同一人兼任负责人，两种账户也分别登记。纯静态部署的账户校验和会话在浏览器内执行，各浏览器分别进行首次登记。

### 签发账户

签发工具需要 Python、openpyxl 和 cryptography。使用 `python tools/provision_accounts.py --help` 查看完整参数。首次独立部署时，可在仓库根目录运行以下示例。将示例中的输入和输出路径替换成本地目录，管理员密码在终端提示时输入。

```powershell
python -m pip install openpyxl cryptography
python tools/provision_accounts.py --students "../private/students.xlsx" --leaders "../private/leaders.xlsx" --signing-key "../private/account-signing-key.pem" --output "../private/accounts" --public-module "dist/assets/account-public.mjs"
```

工作簿需包含「姓名」「班级」「学号」三列。工具会交叉核对两份名单，并按班签发个人账户。重新签发时沿用原私钥，指定新的输出目录。公开部署只需带上校验公钥。学籍、账户文件、私钥、报备回执和统计导出均保存在仓库外。

## 正式办理

1. **管理端准备。** 使用管理员账户登录，核对自动导入的名单。名单变动可在管理端导入 UTF-8 CSV 更新，文件需包含 `姓名`、`班级`、`学号` 三列，学号按文本保存。按任务启用的校区分别配置经校方确认的校园围栏。各校区分别导入 WGS 84 的 GeoJSON Polygon 或 MultiPolygon，允许以 Feature 包装。周边距离和最大定位误差由管理者按实测填写。
2. **发布。** 新建任务，设置北京时间、适用班级和允许校区，确认应报人数后发布。将任务包发到班群，将每班的应报名单私发给该班负责人。延长截止时间和撤销任务均会生成新版本，需要重新转发。
3. **填报。** 学生登录后导入任务包。在校路线使用手机定位，离校路线填写原因。个人回执下载后私发本班负责人。
4. **汇总。** 负责人导入任务、应报名单和学生回执。可按姓名、学号和状态筛选并核验冲突，生成提醒文案及链接，导出本班 CSV，填写情况说明并生成报送包。
5. **收齐。** 管理端导入班级报送包，按发布时的应报名单计算覆盖情况和完成率，并导出汇总或明细。首页入口可直接发给班级，带任务的提醒链接由负责人端生成。

各端底部的“本机数据”提供本地备份下载、最近导入摘要以及已截止或撤销任务的数据清理。备份是供留档的 JSON 快照。跨设备日常交接使用各端的任务包、回执和班级报送包。公开部署只需上传 `dist/`，真实学籍、负责人名单、回执和正式报送数据应通过本机和约定的私聊渠道处理。

## 静态版的边界

文件被接收方导入后才更新对应统计。提醒由负责人转发，因此学生设备只有在收到消息并打开链接后才会显示对应任务。账户文件签名、登录和班级筛选在本机执行。统一鉴权、跨设备撤销账户、防代打卡和自动通知需要共享服务。

## 目录与检查

| 路径 | 用途 |
| --- | --- |
| `dist/` | 静态页面、样式、应用模块和校园素材 |
| `tools/provision_accounts.py` | 从两份名单签发账户 |
| `tests/` | 业务规则和三端浏览器测试 |

用 `node --test tests/model.test.mjs` 检查统计、定位和文件导入规则。浏览器测试使用临时生成的示例账户。启动本地站点后，使用已安装 Playwright 和 Chromium 的环境运行 `node tests/browser.mjs`。可通过 `ATTENDANCE_PLAYWRIGHT` 指定模块位置，通过 `ATTENDANCE_CHROMIUM` 指定 Chromium 可执行文件。
